# 在本库里写文章并发布

这个目录（`src/content`）本身就是一个 Obsidian 仓库，也是 Astro 的内容目录。**在 Obsidian 里写，push，线上就更新**，中间没有后台、没有数据库。

---

## 一、打开仓库

Obsidian → 左下角仓库切换 →「打开本地仓库」→ 选：

```
D:\AstroPaper\capricious-cycle\src\content
```

打开后应该能看到 `blog/`、`projects/` 两个文件夹。编辑器分隔符下面那条栏是 Obsidian Git 的同步状态。

## 二、新建一篇文章

`Ctrl/Cmd + P` → 输入 **Astro Composer: 新建内容** → 选「文章」→ 输入名字。

> 名字会变成 URL 的一部分（`/blog/<名字>/`），**必须用英文短横线**，例如 `my-first-post`。
> 中文标题写在正文开头的 `title` 字段里，不影响地址。

生成的文件长这样：

```
src/content/blog/my-first-post/index.md
```

内容是这个模板：

```yaml
---
title: "这里写标题"
description: ""
pubDate: "2026-10-22"
tags: []
draft: false
---
```

- `title`、`description`、`pubDate` 是**必填**，缺了构建会失败
- `description` 会出现在列表、RSS 和搜索结果里，写一句话概括
- 日期保持带引号的形式，避免不同时区下差一天
- 草稿就把 `draft: false` 改成 `true`，push 上去也不会出现在线上
- 可选字段：`updatedDate`、`image`（列表卡片封面）、`audio: false`（关掉朗读按钮）

## 三、写正文

正文就是普通 Markdown。几个和这个站有关的点：

| 想做的事 | 写法 |
| --- | --- |
| 二级标题自动进目录 | `## 标题`（`###` 不进目录） |
| 提示框 | `> [!TIP]` + 下一行 `> 内容`（还支持 NOTE / IMPORTANT / WARNING / DANGER） |
| 图片 | 直接把图片拖进笔记，会落到同目录，引用写成 `![](cover.png)` |
| 代码高亮 | 围栏代码块标注语言，右上角自动有复制按钮 |
| 站内链接 | 用相对路径 `[标题](/blog/另一篇/)`，**不要用 `[[双链]]`（Astro 不认）** |

## 四、本地看效果（可选）

`Ctrl/Cmd + P` → **Astro Composer: 打开项目终端**（或自己在仓库根目录开终端）：

```powershell
npm run dev        # http://localhost:4321
```

改完 `Ctrl + C` 停掉。

## 五、发布

左侧栏 Obsidian Git 面板 → **Commit-and-sync**（或 `Ctrl/Cmd + P` → `Obsidian Git: Commit-and-sync`）。

它做三件事：拉取远端 → 提交全部改动 → 推送。推送后 GitHub Actions 自动构建，**约 2 分钟**线上更新。

发布后可以自查：

- `https://solitudefurina.github.io/blog/你的-slug/` 是否 200
- 仓库的 **Actions** 页最新一次运行是不是绿色

## 六、几条硬规矩

1. **slug 发布后不要改**。改目录名等于换地址，外部链接和搜索索引都会失效。想改标题就改 `title` 字段。
2. **别在仓库里放大文件**。图片先压缩；仓库会永久保留历史版本。
3. **别提交 `dist/` 和 `node_modules/`**。`.gitignore` 已经忽略，别手动 `git add -f`。
4. **一次发布一篇更好查**。几篇一起推也没问题，但出错时不容易定位是哪篇。
5. `.obsidian/` 里是这套写作环境的配置（模板、附件目录、Git 同步），可以一起提交，换电脑后直接复用。

## 七、上传失败怎么办

Obsidian Git 点 Commit-and-sync 之后没反应、状态栏报错，先分清是哪一层：

| 报错里出现 | 说明 | 处理 |
| --- | --- | --- |
| `Failed to connect` / `Connection was reset` / `port 443` | 网络到 GitHub 不通（最常见） | 换网络重试，或等几分钟 |
| `Permission denied (publickey)` | SSH 密钥没配好 | 确认 remote 是 SSH、密钥已加到仓库 |
| `rejected` / `non-fast-forward` | 本地和远端分叉了 | `git pull --rebase` 再推 |
| `build failed`（Actions 里红叉） | 文章 frontmatter 或代码有问题 | 看 Actions 日志里第一行报错 |

判断是不是纯网络问题，在仓库根目录跑：

```powershell
Test-NetConnection github.com -Port 443 -InformationLevel Quiet
```

返回 False 就是网络，跟文章格式无关。

### 本机当前配置（2026-10 切换）

GitHub 的 443 端口在这台机器上经常被重置，所以 remote 已改成 **SSH**，并且 `C:\Users\A\.ssh\config` 里让 `github.com` 走 `ssh.github.com:443`（这个入口实测通）：

```
git@github.com:SolitudeFurina/SolitudeFurina.github.io.git
```

用的是仓库级的 deploy key（只对这一份仓库有写权限），所以 Obsidian Git 同步现在走 SSH，不再受 443 封锁影响。

自检命令：

```powershell
ssh -T git@github.com
# 期望：Hi SolitudeFurina/SolitudeFurina.github.io! You've successfully authenticated
```

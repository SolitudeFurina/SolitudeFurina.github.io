本站的文章就是普通 Markdown，只是一些细节被增强过。下面这份速查表按“写的时候真的会用到”排序。

## 基础语法

```markdown
# 一级标题（正文里一般不用，标题来自 frontmatter）
## 二级标题  ← 会被收进右侧目录
### 三级标题

**加粗**  *斜体*  `行内代码`
[链接](https://example.com)
> 引用

- 无序列表
1. 有序列表

| 表头 | 表头 |
| --- | --- |
| 单元格 | 单元格 |
```

> [!TIP]
> 二级标题（`##`）会自动出现在右侧目录里。三级标题不会——标题太多会让目录失去导航作用。

## 代码块

围栏代码块支持语言标注，会做语法高亮，并且右上角有复制按钮：

````markdown
```ts
export function greet(name: string) {
  return `你好，${name}`;
}
```
````

## 提示框

用 GitHub 风格的 blockquote 语法，支持五种类型：

```markdown
> [!NOTE]
> 补充说明。

> [!TIP]
> 小技巧。

> [!IMPORTANT]
> 必须注意的事。

> [!WARNING]
> 可能出错的地方。

> [!DANGER]
> 危险操作。
```

> 提示框的第一行是标题，后面才是正文。类型写错会退化成普通引用。

## 图片

把图片放进 `public/images/`，用绝对路径引用：

```markdown
![描述文字](/images/example.png)
```

点击图片会放大查看（本站开了 imageZoom）。

> [!WARNING]
> `public/` 里的文件会按原样发布，**不做压缩**。上传前先把大图压一下，否则一篇文章几 MB 很常见。

## frontmatter 速查

```yaml
---
title: '文章标题'          # 必填
description: '摘要'        # 必填，会用于列表、RSS 和搜索
pubDate: '2026-10-17'      # 必填
updatedDate: '2026-10-18'  # 可选，显示“更新”标记
tags: ['标签一', '标签二']  # 可选
draft: true                # 可选，草稿不会被发布
image: '/images/cover.png' # 可选，列表卡片封面
---
```

> [!NOTE]
> 日期写成 `'2026-10-17'` 这种带引号的字符串，不要写成 `2026-10-17` 这种裸日期——YAML 会把它解析成别的东西，时区一换日期就可能差一天。

## 写作节奏的一点建议

- 先写完，再改。边写边改容易卡在第一段。
- 一段只讲一件事。长了就断开。
- 标题写“结论”，不写“话题”。`## 构建发生在 CI 里` 比 `## 关于构建` 有用得多。
